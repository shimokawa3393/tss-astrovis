# TSS ep1 Blender制作の教訓（BGM入りで完成、投稿は未。2026-11-03時点）

台本「太陽を望遠鏡にする」（TSS Astrovis 第1話、太陽重力レンズ）。進捗は `進捗報告書.md`（リポジトリのルート）、台本は `tss-ep1/md/Tss 第1話 台本.md`。
49秒・7カット、ナレーションなし、テロップで進める。10-24に台本、10-25に静止画、11-01にアニメーションからフルレンダーまで、11-03にBGM。

## 台本・構成

- **台本の段階で「何ができるのか」（オチの具体的な数字）が抜けていた**。ユーザー「SGLで何ができるかとかいらないの？」で④結に足した（37秒→44秒）。
  仕組みの話（光が曲がる・線に集まる・548AU）だけでは、オチが名前だけになる。
- **ドラフトを見せると「説明が足りない」所が出る**。「レンズが光を集めるのと、重力で光を集めるのがピンとこない」「1AUの距離感がわからない人がほとんど」。
  作る側は仕組みを知っているので気づきにくい。言葉を足すだけでなく、絵でつないだ:
  - レンズが縮みながら同じ位置の太陽に変わる（1a→2a）。テロップも「光を**曲げて**集める」「太陽の重力も光を**曲げる**」と言葉をそろえた
  - 知っている物の目印（海王星・ボイジャー1号）を、目盛りの横に名前だけで置いた。目印を足す案（冥王星・太陽圏の果て・光で何日）は「そのままでいいや」
- **テロップは絵と同じ対にすると伝わる**。4bは「月より大きい鏡が要る ↔ 口径1mで100万画素」が「ピンとこない」（口径は普段使わない言葉、
  100万画素はスマホより少なく聞こえる）。ユーザーの案で「ふつうの望遠鏡では点にしか見えない ↔ 太陽を使えば大陸まで見える」にした。
  数字の比較や専門の言葉は投稿文へ。
- **テロップの語順と出すタイミング**。「1AUは地球と太陽の距離」→「地球と太陽の距離は1AU」（文が数字で終わり、次の548AUと並ぶ。ユーザーの案）。
  出すのは目盛りの「100 AU」が流れてくる瞬間（見る人が「AUって何？」と思う時）。最初は太陽で止めて出したが「タイミングが違う」。
- **「その」は間に別のテロップが入ると指す物が分からない**（「その線が始まるのは」をユーザーが止めた）。
- **名前（オチ）は最後まで出さない**。「SGLなら」と略称を途中で出すと、4cの名前の発表が先に割れる。
- 最後の名前だけ中央・1.2倍。位置の一貫性は崩れるが、「説明」と「名前の発表」で役割が違うので採用。背景は暗転→3aの引きの絵→「ただの宇宙でいい」。

## スケールと正確さ

- **台本の誇張率（1万倍）は、画面で描いてみるまで良し悪しが分からなかった**。着手前の2Dスケッチ（`00_scale_check.py`）で3万倍に決められた。
- **横方向だけ誇張した絵では、太陽の大きさ・光線の曲がり方・海王星の距離が同時には合わない**。カットごとに何を合わせるか決める
  （交わる位置は計算どおり、太陽は記号の大きさ）。
- **「その場から見た景色」のカットでは、記号の大きさが嘘になる**。4aで太陽を円盤に描いて「いいじゃん！」の後、ユーザー「リアルな話、太陽こんなに
  大きく見えないでしょ？」。1200AUでは見かけの直径約1.6秒角で、目には点。目で見た太陽は点にし、円盤と光の輪は「望遠鏡の視野」の中に描いた
  （口径1mなら分けて見える）。2a・3aのような模式図と、視点のある景色は扱いを分ける。
- 光の輪の半径（太陽の1.48倍）のように、誇張した絵の中でも実物どおりにできる比は実物どおりにする。
- **ネタ（「アップで宇宙人が手を振る」）は、画素の大きさで判断した**。1000×1000画素では1画素が約13km四方で、人や建物は見えない。
- 数字は出典を確かめてから出す。ボイジャー1号の距離は JPL Horizons の API で当日の値（172.2AU）を取った。
- 地球の画像は「日本を少し右に」まで詰めたが、最後は「未知の惑星感を出したい」で架空の惑星（ノイズで海・大陸・雲・氷）にした。
  論文が地球の画像で試算していることは投稿文に書く。

## 見た目の決め方

- **見た目の質感の相談（「リアルにならない？」）は、静止画を1枚ずつ見せて決める**。1aのレンズで、立体のガラス・見下ろし・映り込み（スタジオの写真、
  自作の照明）まで進めたが、ユーザーが欲しかったのは「線だけ」で「厚み・まっすぐな側面・レンズっぽい色」だった。言葉の「リアル」を作る側は
  立体・材質と受け取りがち。「材質か、形か、色か」を先に聞けば往復が減った。並べて見せると決まるのも早い（角あり／丸めを並べて「角ありでゴー」）。
- **黒い背景ではガラスは描けない**。映るものがないので、灰色の円盤か白い光の玉になる。
- 探査機は最初、筒・箱・腕だけで「雑すぎた！笑」。実際の遠くへ行く探査機によくある部品（RTG、皿のアンテナ、金色の断熱材、ノズル、星を見るカメラ）
  で組むと、それらしくなった。部品の理由（1200AUでは太陽電池が使えない、地球は太陽とほぼ同じ方向）も説明できる。
- 太陽のコロナは筋を入れると「ないわ笑」。なめらかなにじみだけにした。

## 制作の進め方

- **構成（`cuts.py`・`scene_state`・`build_frame`）を静止画と連番で共有すると、直しが速い**。絵が静止画の段階で決まっていたので、
  アニメーションの組み立てからフルレンダーまで1日で済んだ。毎フレーム組み直す作りにして、線の太さを画面の画素で保った（引きや下りの最中も細いまま）。
- **ドラフト（4分の1の解像度・2フレームに1枚）は動きの確認に速い**（49秒分が約2分半）。ただし小さな文字は潰れて大きさの良し悪しが分からない。
  目盛りの文字（26px）はドラフトで「小さすぎて見えない」→42pxに。テロップと目盛りの重なりも本番の解像度で初めて見えた。文字は本番の解像度のコマで見る。
- **フルレンダーは途中から見られるようにする**。`video.py --range` で描けた所までをmp4にし、出だし14秒を先に送った。本番は発光だけの絵で1枚1〜3秒（EEVEE）、
  1440枚で約43分。直しはカット単位で撮り直す（4bの延長、4c、探査機の4a）。
- ユーザーはリモート（スマホ）で見ていたので、静止画・並べた画像・動画はその都度送った。

## Blender・実装

- **半透明の球は裏側の面を描かない**。描くと、裏と表が重なる順番の境目が球の上に線で出て、明るくなるにつれて動き、「光が右から左へ移動している」
  ように見えた（`mat.use_backface_culling = True`）。
- 暗いだけの球は、後ろの物を黒い円で隠す。現れる途中は透かす。
- 金属感を強くすると、黒い宇宙を映して真っ黒になる（探査機は metallic 0.2〜0.35）。
- 色の変換は Standard（AgX は明るい太陽のオレンジがピンクに抜けた）。VSE でも Standard（ep4の教訓どおり）。
- 縦型の画面に置くテロップと絵は、上の帯（上から約11〜25%）を空ける。3aの太陽と4aの視野をテロップの下へずらした。右下はSNSのボタンがかぶる。
- zsh では `set -- $変数` で単語に分かれない（ep5と同じ）。

## BGM・投稿文

- **「exactly 49 seconds」で頼むと、ファイルは49秒になるが、曲は早く終わることがある**。温かい版は43秒から小さくなり始め、47.5秒で無音
  （映像は46秒の和音を49秒まで響かせる予定）。ユーザー「曲が終わるの早くない？」。音量を0.25秒ごとに出すと、終わる位置がすぐ分かる。
  42〜46秒に頼んだ一番の盛り上がりも出ず、21秒から最後までほぼ同じ音量だった（ep4の教訓どおり、音量の山は出にくい）。
- **曲を作り直さずに、一定のテンポで進む所へ1小節（90BPMで2.67秒）をもう1回入れて伸ばせた**。入れる位置は、1小節ずらした音が一番似ている所
  （23.4秒）。つなぎ目は0.04秒重ねる。これで終わりが46秒にそろい、ユーザー「いいね👍」。頭をずらす方法は出だしが無音になるので使わなかった。
- **ループで曲を伸ばすのは、私が耳で聴けないので3回続けて外した**（おまけで ep4 の30秒の曲を伸ばした時）。
  パートごと丸ごと繰り返す（A→A→B→B）は「継ぎ目まで行ったらループ」に聞こえ、パートの中の1小節を繰り返すと「壊れたのかな？」、
  音の似ている所を数値で選んでも「論外」。数値で似ていても、音楽のフレーズとして自然とは限らない。1小節を1回だけ足すのはうまくいったが、
  同じ所を何度も回すと粗が出る。伸ばしたい時は、繰り返す区間をユーザーに耳で決めてもらうか、最初から欲しい長さで生成する。
- 投稿文は「もう少しコンパクトに」。100万画素・3800kmの数字を外し、注記を3行にまとめた。出典と CC BY 4.0 のクレジットは残す。
- ユーザーはリモートで見ているので、プロンプトは会話にテキストで貼り、動画はファイルで送る。

## 次回への提案

- 台本の段階で「この動画を見て何ができると分かるか」と、各テロップが絵のどこを指すかを書く。
- 視点のある景色のカットは、着手前に見かけの大きさを計算する。
- 見た目の要望は「材質・形・色・大きさ」のどれかを聞いてから作る。
- 文字の大きさと重なりは、ドラフトでなく本番の解像度のコマで確かめる。
- 生成した曲は、映像に入れる前に音量の変化を出して、終わり始める位置と盛り上がりの位置を映像と比べる。短く終わる曲は、一定のテンポの所へ1小節足して合わせる。
