# 550AU自立制御フェーズ（入門編）  
  
———  
  
TSS-550 自律制御フェーズ 入門編  
  
2026/05/04 現在  
  
	0.	なぜ完全自律が必要か  
  
550AUから地球まで電波で約76時間。修正命令を送って返事が来るまで約152時間（約6.4日）。その間に探査機は止まらない。姿勢がズレ続ける、センサーが壊れる、予期しない重力影響を受ける——どれも「待ってから対処」では手遅れになる。  
  
だから探査機は地球の指示なしで、自分で状況を判断し、自分で行動を決める必要がある。これが完全自律の出発点。  
  
	1.	完全自律の判断システム  
  
完全自律の判断システムとは「センサーで現状を把握して、判断して、アクチュエータを動かす」ループを永遠に回し続けるシステム。  
  
センサー → 状態推定 → 判断 → 行動 → （また最初へ）  
  
このループを制御ループ（コントロールループ）と呼ぶ。Phase 1のFCで実装した状態機械（IDLE→LAUNCHED→COAST…）も、このループの一形態だった。  
  
判断の作り方には大きく2つある。  
  
① ルールベース（Rule-Based）  
人間が事前に「もしAが起きたらBをしろ」を全部書いておく。シンプルで信頼性が高く、何をするかが完全に人間に見える（Verifiability・検証可能性）。弱点は想定外に対応できないこと。  
  
② 学習ベース（Machine Learning）  
データから判断のパターンを自動で学ぶ。想定外にも柔軟に対応できる可能性がある。弱点は「なぜその判断をしたか」が見えにくいこと。失敗が許されない宇宙機では採用ハードルが高い。  
  
現実の宇宙機はルールベースが主役で、学習ベースは補助という構成が多い。VoyagerもMROも、基本はルールベースの状態機械で動いている。  
  
	2.	状態機械（State Machine）  
  
ルールベースの判断システムの中核。構成要素は3つ。  
  
状態（State）：今どういう状況にいるか  
遷移条件（Transition）：どうなったら次の状態に移るか  
アクション（Action）：その状態のときに何をするか  
  
550AUの探査機で考えると：  
  
CRUISE（巡航中）  
　→ 異常検知 → SAFE_MODE  
　→ 焦点到達 → OBSERVATION  
  
SAFE_MODE  
　→ 電力回復 → CRUISE  
　→ 復旧不能 → MINIMAL（最小生存モード）  
  
OBSERVATION  
　→ データ取得完了 → TRANSMIT  
　→ 異常 → SAFE_MODE  
  
状態が増えれば増えるほど「想定外」が減る。設計者が「こういう状況が起きうる」と認識した分だけ状態として定義しておく。  
  
	3.	セーフモード（Safe Mode）  
  
異常が起きたとき、探査機が自律的に移行する「最低限の生存だけを維持して、地球からの指示を待つ状態」。  
  
やることはシンプル。  
・太陽に向けて電力を確保する  
・地球に向けてアンテナを向ける  
・非必須システムを全部止める  
・「助けてくれ」信号を送り続ける  
  
VoyagerもCassiniも、実際に何度もセーフモードに入っている。異常をゼロにするのではなく、異常が起きても死なない設計——これが宇宙機設計の核心思想。  
  
	4.	判断システムの階層構造  
  
完全自律の判断は1つの巨大なシステムではなく、階層構造になっている。  
  
【高レベル】ミッション管理  
　何をするか（観測する・送信する・省電力にする）  
　　↓  
【中レベル】モード管理（状態機械）  
　今どの状態か・どの状態に移るか  
　　↓  
【低レベル】制御ループ（PID等）  
　姿勢・電力・熱をリアルタイムで調整する  
  
Phase 1のFCは低レベルと中レベルを実装していた。Phase 2のドローンで中レベルをもっと本格的に作ることになる。  
  
	5.	異常検知・自己修復  
  
5-0. 問題の本質  
  
故障しないシステムを作るのは不可能。故障しても死なないシステムを作る——これが出発点。  
  
5-1. 異常の種類  
  
ハード故障：センサーが完全に壊れる。突発的・回復不能なことが多い。  
ソフト異常：宇宙線でメモリのビットが反転する（SEU・Single Event Upset）。一時的・リセットで回復することも。  
性能劣化：RTGの出力が少しずつ落ちる。緩やかで気づきにくい。  
環境異常：予測外の重力影響・磁場変化。センサー値が「おかしい」形で現れる。  
  
5-2. 異常検知の3つのアプローチ  
  
① 閾値監視（しきいちかんし）  
センサー値が正常範囲を超えたら異常とみなす。実装が簡単で信頼性が高い。ただし「じわじわズレていく」劣化には気づきにくい。  
  
② 冗長センサーの多数決（Triple Modular Redundancy・TMR）  
同じものを3つ積んで多数決で正解を決める。NASAの基幹システムはほぼ全部これを使っている。  
  
③ モデルベース検知  
「こういう状況ならセンサー値はこうなるはず」という物理モデルと実測値の乖離で異常を検知する。OpenRocketのシミュレーションと実測を比較したのと同じ発想。  
  
5-3. 自己修復の手段  
  
① リセット  
一番原始的で一番効く。ソフト異常の多くはリセットで直る。全体リセットではなく異常が起きたサブシステムだけ再起動できる設計が理想。  
  
② フォールバック（Fallback）  
壊れたものを切り捨ててバックアップに切り替える。性能が落ちても生き続けることを優先する。  
  
③ パラメータ再調整  
壊れてはいないが劣化している場合。RTGの出力が落ちてきたら消費電力を絞る、スラスタの効率が落ちてきたらPIDゲインを再調整するなど。これを適応制御（Adaptive Control）と呼ぶ。  
  
5-4. ウォッチドッグタイマー  
  
一定時間ごとに生存確認をして、応答がなければ強制リセットするタイマー。  
  
正常時：メインシステムが定期的に「生きてるよ」信号を送信。ウォッチドッグはタイマーをリセットし続ける。  
異常時：フリーズして信号が来なくなる → タイマー満了 → 強制リセット実行。  
  
ESP32にも内蔵されている。宇宙機ではウォッチドッグが止まること自体が最悪のシナリオなので、最も信頼性の高いハードウェアで実装される。  
  
5-5. メモリ保護（ECC）  
  
宇宙放射線によるビット反転（SEU）への対策。  
  
ハード対策：放射線耐性メモリ（Radiation Hardened Memory）。製造プロセス自体を放射線に強く作る。  
ソフト対策：ECC（Error Correcting Code）。データに冗長な情報を付け加えておいて、ビット反転が起きても元のデータを復元できるようにする。通信フェーズのReed-SolomonやLDPCと同じ仲間。  
  
	6.	姿勢制御（150年間）  
  
6-0. 問題の本質  
  
550AUで焦点線に乗り続けるためには、探査機が常に正確な方向を向いている必要がある。レーザー通信のビーム幅は0.000003°。これを自律的に維持し続けなければいけない。  
  
6-1. 姿勢制御に使う3つの道具  
  
① 測る：センサー群  
  
スタートラッカー：星の位置から姿勢を特定。太陽・月が視野に入ると狂う。  
IMU（慣性計測装置）：角速度・加速度を計測。時間とともに誤差が積み上がる（ドリフト）。  
太陽センサー：太陽の方向を計測。太陽から遠ざかると精度が落ちる。  
  
複数センサーを組み合わせて互いの弱点を補う。  
  
② 計算する：カルマンフィルター（Kalman Filter）  
  
センサーの値と物理モデルの予測を組み合わせて、最も確からしい状態を推定するアルゴリズム。  
  
物理モデルの予測 → 「このくらいの姿勢のはず」  
センサーの実測値 → 「こう測れた（ノイズ込み）」  
カルマンフィルター → 両方を重み付けして最良推定値を出す  
  
Phase 1のPIDでKdにノイズフィルタリングが必要だった話の、もっと本格的な版がこれ。NASAのほぼ全ての宇宙機に使われている。  
  
③ 動かす：アクチュエータ  
  
冷ガススラスタ：ガスを噴射した反動で回転。シンプルだがガスを消費する。  
リアクションホイール：回転体を加減速した反動で姿勢変化。ガス不要・長期向き。  
CMG（制御モーメントジャイロ）：ホイールの向きを変えて大きなトルク。高精度・複雑。  
  
550AUまでの長期ミッションではリアクションホイールが主役。  
  
6-2. リアクションホイールの仕組みと問題  
  
椅子に座った状態でホイールを右回転させると体が左回転する——これが原理。電気さえあれば動くのでRTGと相性がいい。  
  
問題はサチュレーション（飽和）。ホイールが回転数の上限に達すると姿勢制御ができなくなる。解消するためにときどきガスを噴射してホイールの回転数を逃がす（デサチュレーション）必要がある。だからガスを完全にゼロにはできない。  
  
6-3. 慣性航法（INS）  
  
GPSが使えない深宇宙で位置を知る手段。加速度センサーとジャイロの積分で位置と速度を推定し続ける。  
  
加速度を積分 → 速度  
速度を積分　 → 位置  
  
問題はドリフトが積分で増幅されること。これをスタートラッカーによる天体観測と組み合わせてカルマンフィルターで統合することで、長期間でも誤差が発散しない推定が可能になる。  
  
慣性航法（連続・高頻度だが誤差が積み上がる）  
　　＋  
天体観測（離散的・低頻度だが絶対精度が高い）  
　　↓  
カルマンフィルターで統合  
　　↓  
長期間でも誤差が発散しない推定  
  
	7.	自律制御フェーズ全体のつながり  
  
完全自律の判断システム  
　└── 状態機械で「今何をすべきか」を決める  
　　　　↓  
異常検知・自己修復  
　└── 判断システムに「異常かどうか」を教える  
　　　　↓  
姿勢制御  
　└── 判断に基づいてアクチュエータを動かす  
　　　カルマンフィルターで「今どっちを向いているか」を推定  
　　　リアクションホイールで「正しい方向に向け続ける」  
  
3つは別々の話ではなく、1つのシステムの層構造になっている。  
  
そして通信フェーズで出てきたAPTシステム（レーザーの自律追尾）は、この姿勢制御の上に乗っかっている。  
  
「異常をゼロにする」ではなく「異常が起きても死なない」——これが150年間動き続けるシステムの設計哲学。
