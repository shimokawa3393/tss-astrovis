## 0. なぜ自律制御の問題が「変わるか」

TSS-550の核心は、「片道約76時間の遅延で、地球から操作できない」ことだった。

火星の遅延は、地球との距離によって片道約3〜22分、往復で約6〜44分。「550AUより短いから楽」ではない。問題の性質が根本から違う。

火星のドローンは高度5〜12mを飛ぶ。岩に当たるまで数秒しかないので、飛行中の判断はミリ秒〜秒単位で、機体がリアルタイムに行う必要がある。

| | 対処までに使える時間 |
|---|---|
| TSS-550 | 異常が起きてから数時間で対処すればよい |
| TSS-Mars | 異常が起きてから数秒で対処しないと墜落する |

## 1. 遅延前提の判断システム設計

地球が送れるのは高レベルの指令だけ。低レベルの判断は、全て機体が自律で実行する。

| 担当 | 中身 |
|---|---|
| 地球 | 「A地点からB地点を探索せよ」 |
| 機体 | 飛行・障害物回避・着陸・緊急対応 |

地球の指示が届かない時間は、遅延だけではない。

| 地球の指示が届かない時間 | 長さ |
|---|---|
| 片道の遅延 | 約3〜22分 |
| 中継機のウィンドウの合間 | 数時間 |
| 太陽合(約26か月ごと) | 約2週間 |

太陽合の間は、事前に送っておいた運用計画だけで、機体が2週間動く。

550AUと同じ階層構造だが、火星ではSLAMが加わる。

```
高レベル
  「A → B を探索せよ」(地球が送る)
        ↓
中レベル①
  今どこにいるか? 地形はどうなっているか?(SLAM) ← 火星で追加
        ↓
中レベル②
  今どのモードか(状態機械)
        ↓
低レベル
  姿勢制御・モーター制御
```

## 2. 未知地形のリアルタイム認識(SLAM)

### SLAMとは

SLAM(Simultaneous Localization and Mapping)は、飛びながら地図を作り、同時に自分の位置を推定し続ける技術。

### Ingenuityの教訓

Ingenuityは、下向きのカメラで地面の模様(特徴点)を追いかけて、自分の動きを推定していた。最後の飛行(2024年1月)では、模様の少ない砂地の上を飛んだため、カメラが追える特徴が足りず、位置と速度の推定が狂った。着陸のときに砂丘の斜面へ強く降りて姿勢を崩し、4枚のローターブレードがすべて壊れた(NASAの調査)。

だからTSS-Marsでは、模様に頼らず距離を直接測れるLiDARを必須にする。

| センサー | 取れる情報 | 役割 |
|---|---|---|
| LiDAR | レーザーで測った距離 | 3D点群・地形の把握。模様のない砂地でも形は測れる |
| カメラ | 見た目 | 特徴点の追跡 |

### 位置推定の本質

```
周囲の物体との距離の変化
        ↓
自分がどの方向へ、どれだけ動いたかを計算
        ↓
1秒前の位置 + 移動量
        ↓
現在位置
```

ただし、計算を積み重ねるほど誤差も積み重なる。550AUのIMUと同じドリフトの問題。

### 補正の手段: ループクロージャ

```
飛びながら地図を作る
        ↓
「この地形は前に見た」と判定する
        ↓
積み上がった誤差をリセット
        ↓
位置を再補正
```

模様のない平坦な地形では、「前に見た」と判定する手がかりも少ないので、ループクロージャも効きにくい。

## 3. 障害物回避アルゴリズム

全体の大まかなルート計画(Global Planning)と、目の前の回避(Local Planning)を組み合わせる。

| 種類 | アルゴリズム | 用途 | 必要な地図 |
|---|---|---|---|
| Global Planning | A*(エースター) | 大まかなルート計算 | 広い範囲の地図 |
| Local Planning | RRT(ランダムツリー) | リアルタイムの回避 | 目の前の点群などの局所的な地図 |

### A* の仕組み

現在地から目的地まで、コストが最小になるルートを探す。

$$\text{コスト} = \text{距離} + \text{障害物回避のコスト}$$

### RRT の仕組み

```
現在位置から、ランダムに枝を伸ばす
        ↓
障害物に当たった枝を切る
        ↓
目的地へ届く枝を探す
        ↓
リアルタイムで繰り返す
```

## 4. 異常検知・自己修復

火星には、550AUにはない固有の異常が2つある。

### 砂嵐の検知

```
発電量が急落
        ↓
砂嵐と判定
        ↓
サバイバルモードへ移行
  ヒーターだけ動かす
  通信は間欠送信
  飛行・センシングは停止
        ↓
晴れるまで待機
```

風速センサーを使わなくても、発電量の変化そのものが砂嵐の検知器になる。シンプルで壊れにくい。

### 転倒の検知

```
ロール・ピッチが90°を超える(IMUで検知)
        ↓
全モーター停止
        ↓
地球へ通報「転倒した」「位置はここ」
        ↓
Optimusか次のミッションを待つ
```

転倒は自己修復できない異常として扱う。「直す」のではなく、「死なずに助けを待つ」という設計思想。550AUのセーフモードと同じ考え方。

### 異常検知の一覧

| 異常 | 検知手段 | 対応 |
|---|---|---|
| 砂嵐 | 発電量の急落 | サバイバルモードへ移行 |
| 転倒 | IMUの姿勢角 | モーター停止、救助待ち |
| SLAMの失敗 | 推定の信頼度スコアの低下 | その場でホバリングして再スキャン、だめなら安全な場所へ着陸 |

太陽合は異常ではなく、事前に分かっている予定。検知は要らず、運用計画の側で扱う(通信フェーズ第5章)。

## 5. 姿勢制御(火星環境)

基本構造はChapter 2のF450と同じ。4つのプロペラの回転数を制御して、ロール・ピッチ・ヨーを調整する。

### 火星固有の問題

火星の大気密度は地球の約1/60しかない。そのため、空気による揺れの減衰(ダンピング)がとても弱い。

```
地球                         火星
突風                         突風
 ↓                            ↓
機体が傾く                    機体が傾く
 ↓                            ↓
空気抵抗が働く                戻す力がとても弱い
 ↓                            ↓
自然に戻る                    傾き続ける
```

### PID制御のトレードオフ

| 調整 | メリット | デメリット |
|---|---|---|
| 応答速度を上げる | 突風へ素早く対応できる | 振動しやすい |
| 応答速度を下げる | 振動しにくい | 突風に負ける |

地球では空気抵抗がこの問題を和らげていた。火星ではそれが期待できない。

### 解決策: カルマンフィルター

```
センサーの実測値(ノイズあり)
    +
物理モデルの予測(このくらい傾くはず)
        ↓
カルマンフィルターで統合
        ↓
高精度な姿勢推定
        ↓
PIDへの入力が安定し、過剰反応が減る
```

### 最終構成

```
PID制御(地球と同じ基本構造)
  + カルマンフィルター(入力の安定化)
  + 火星環境向けのチューニング
```

## TSS-550との差分まとめ

| 項目 | TSS-550 | TSS-Mars |
|---|---|---|
| 遅延 | 片道約76時間(往復約6.4日) | 片道約3〜22分(往復約6〜44分) |
| 判断の時間軸 | 時間〜日単位 | ミリ秒〜秒単位 |
| 地球の指示が全く届かない時間 | 太陽の向こう側に隠れる時期(目標の方向による) | ウィンドウの合間(数時間)、太陽合(約2週間) |
| 地形認識 | 不要 | SLAMが必須 |
| 障害物回避 | 不要 | A* + RRT |
| 固有の異常 | 宇宙線、機器の劣化 | 砂嵐、転倒 |
| 姿勢制御の目標 | レーザーを数µradの精度で向け続ける | 突風へ素早く対応する |
| 姿勢補正の手段 | 大気なし、ホイールとスラスタ | 大気が薄い、カルマンフィルターで補う |

## 一言まとめ

**TSS-550** は、宇宙という静かな環境で、長期間正確に動くための設計。

**TSS-Mars** は、地形・砂嵐・障害物という動く環境を、リアルタイムで切り抜けるための設計。
