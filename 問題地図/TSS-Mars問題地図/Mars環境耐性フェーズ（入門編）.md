# Mars環境耐性フェーズ（入門編）

> TSS-Mars 環境耐性フェーズ 入門編 ・ 初版 2026-06 ・ 改訂 2026-10-25

---

## 概要

火星の極限環境で、機体が「壊れない・止まらない・動き続ける」ための設計思想。地球用のドローン(F450)をそのまま火星へ持っていくと、飛ぶ前に壊れる。

## 1. 極低温対策

### 問題の本質: バッテリーが最初に死ぬ

| 項目 | 温度 |
|---|---|
| リチウムポリマーバッテリーの動作範囲(放電) | 約−20℃〜+60℃ |
| 火星の夜 | 約−80〜−90℃ |

低温では電解液の動きが鈍り、電圧が保てなくなる。さらに冷えると凍って、バッテリーそのものが壊れる。CPUより先にバッテリーが死ぬ。だから、熱設計の最優先は「バッテリーを守る」こと。

### 設計思想: マトリョーシカ構造

```
火星の大気
 └─ 外壁
     └─ 断熱層(エアロゲル・断熱用のガス層)
         └─ ヒーター
             └─ バッテリー(中心)
```

### 断熱材の選択肢

| 素材 | 特徴 | 火星の地表での使い方 |
|---|---|---|
| エアロゲル | 世界最軽量クラスの固体。熱を伝えにくい | 断熱の主役。火星探査車(SojournerやMERなど)の保温箱で使われてきた |
| 断熱用のガス層 | 薄いCO₂のすき間を断熱に使う | 軽くできる |
| MLI(多層断熱材) | 放射の熱を反射する。宇宙機の標準 | 真空でよく効く。火星の薄い大気の中では、層の間をガスが熱を運ぶので効きが落ちる |
| 防災用アルミシート | 安い。真空近くでガスが出る(アウトガッシング) | 地上試験だけ |

**防災シートを本番で使えない理由:** 真空に近い環境でガスが出て、センサーのレンズや基板の接点を汚す(アウトガッシング)。

### 熱設計の計算の考え方

電気回路のオームの法則と同じ構造で考えられる。

$$\Delta T = Q \times R_{th}$$

| 記号 | 意味 | 電気回路では |
|---|---|---|
| $\Delta T$ | 温度差 | 電圧 |
| $Q$ | 熱の流れ(W) | 電流 |
| $R_{th}$ | 熱抵抗 | 抵抗 |

たとえば、外が−80℃でバッテリーを−15℃に保つなら $\Delta T = 65$ K。ヒーターに使える電力が1Wなら、必要な熱抵抗は $65 \div 1 = 65$ K/W。「バッテリーを何℃以上に保つために、熱抵抗をいくつ以上にするか」を数字で設計する。

### Ingenuityの実績

- 夜間はヒーターで、バッテリーを約−15℃以上に保った
- 昼間に太陽光パネルで充電した
- 電力の多くを、夜のヒーターに使っていた

## 2. 放射線耐性

### 問題の本質: 火星には地球のような磁場がない

| | 宇宙線への守り |
|---|---|
| 地球 | 地磁気と厚い大気が、宇宙線や太陽風を弾く |
| 火星 | 全体を包む磁場がなく、大気も薄い。宇宙線が地表まで届く |

火星の地表の被曝量は1日あたり約0.6〜0.7mSvで、地球の地上の約100倍(Curiosityの観測)。機械にとっては、ビット反転(Single Event Upset)の原因になる。

### ビット反転とは

メモリの0が、高エネルギーの粒子に叩かれて1に化ける。

- プログラムが突然おかしくなる
- センサーの値が化ける
- ソフトウェアのバグではなく、物理現象

最も危険なのは、「動いているのに壊れている」状態。

### 対策①: ウォッチドッグタイマー(WDT)

```cpp
#include <esp_task_wdt.h>

void setup() {
    // Arduino-ESP32 3.x(ESP-IDF 5)の書き方
    esp_task_wdt_config_t cfg = {
        .timeout_ms = 5000,      // 5秒以内にリセットされないと再起動
        .idle_core_mask = 0,
        .trigger_panic = true,
    };
    esp_task_wdt_reconfigure(&cfg);  // 起動時にすでに有効なので再設定する
    esp_task_wdt_add(NULL);          // このタスクを監視対象に入れる
}

void loop() {
    esp_task_wdt_reset();  // 正常に動いている間は定期的にリセット
    // メイン処理...
}
```

(Arduino-ESP32 2.x では `esp_task_wdt_init(5, true);` の書き方だった)

プログラムが固まったときの最終防衛ライン。ただし、「動いているが値だけ壊れている」状態には無力。

### 対策②: 三重冗長(TMR)

独立した3つのセンサー(または3つの計算)の値を比べて、多数決で正解を選ぶ。実際のセンサー値は小数で、完全に一致することはまずないので、「真ん中の値(中央値)」を採るのが実用的。

```cpp
float median3(float a, float b, float c) {
    if ((a >= b && a <= c) || (a <= b && a >= c)) return a;
    if ((b >= a && b <= c) || (b <= a && b >= c)) return b;
    return c;
}

float readAngleTMR() {
    float a = readImuA();   // 独立した3つのセンサー
    float b = readImuB();
    float c = readImuC();
    float m = median3(a, b, c);

    const float TOL = 2.0f;  // 許容差(度)
    int agree = (fabsf(a - m) < TOL) + (fabsf(b - m) < TOL) + (fabsf(c - m) < TOL);
    if (agree < 2) {
        triggerEmergency();  // 2つ以上が食い違う → 異常
    }
    return m;
}
```

1つが壊れても、残り2つで正しい値を保てる。

| やり方 | 守れるもの | 守れないもの |
|---|---|---|
| 同じセンサーを3回読む(時間の冗長) | 一瞬だけの乱れ | センサーそのものの故障 |
| 独立した3つのセンサー(空間の冗長) | センサー1つの故障 | 3つ同時に影響する原因(電源の異常など) |

### TSS-Marsでの使いどころ

- PID計算の入力値 → TMRで守る
- 姿勢角のセンサー → 複数のセンサーで多数決
- 異常値 → 閾値を超えたら前回の値を使う

### ハードウェア側の選択肢

| アプローチ | 中身 | コスト |
|---|---|---|
| 放射線耐性品(Rad-Hard) | 製造プロセスの段階で放射線に強く作る | ESP32の数百円 → 数十万円 |
| 民生品 + TMR | 安い部品 + ソフトウェアの冗長化 | 現実的 |

**Ingenuityの判断:** 民生品のスマホ用プロセッサ(Qualcomm Snapdragon 801)を使い、ソフトウェア側で自己修復・再起動する設計にした。

### TSS-550との共通点

通信フェーズの誤り訂正(冗長な情報を足して、壊れた部分から正解を取り出す)と同じ構造。TSS全体を貫く思想は、「冗長性で信頼性を上げる」。

## 3. 砂嵐・砂塵対策

### 問題の本質: 地球の砂より約100倍細かい

| | 粒の大きさ |
|---|---|
| 地球の砂 | 約0.1〜2mm |
| 火星の塵 | 約0.001〜0.01mm(PM2.5に近い) |

ベアリング、モーターのコイル、基板、コネクタ。あらゆるすき間に入り込む。

### 本質は「風の力」ではない

火星の風は強くても秒速30m程度で、空気が薄いので押す力は地球の約1/60しかない(Mars飛行フェーズ)。問題の本質は、**入り込むことと、削ること**。

### モーターへの影響

| 期間 | 起きること |
|---|---|
| 短期 | 砂が噛む → 回転の抵抗が増える → 消費電力が増える → 電力の問題に直結 |
| 長期 | コイル・ベアリングの摩耗 → 精度の低下 → 最終的に故障 |

### 対策のトレードオフ

| 方針 | メリット | デメリット |
|---|---|---|
| 封止(入れない) | 防塵性能が上がる | 重くなる、放熱が悪くなる |
| 開口(放熱を優先) | 冷やしやすい | 砂塵が入る |
| 断熱(熱を保つ) | 温度を保てる | 密閉が必要 |

設計とは、「どこで折り合いを付けるか」の連続。

### 素材の選定

| 素材 | 特徴 | 使いどころ |
|---|---|---|
| CFRP(炭素繊維強化プラスチック) | 軽い、硬い | ローター、主構造(Ingenuityのブレードも炭素繊維製) |
| チタン | 強い、さびない、摩耗に強い | 接合部、シャフト |
| アルマイト処理したアルミ | 摩耗に強い皮膜、現実的なコスト | 外装カバー |
| DLCコーティング | ダイヤモンドに近い硬さ | ベアリング、可動部 |

「全部同じ素材」ではなく、場所ごとに最適な素材を選ぶ。

### TSS-Marsで現実的な調達ライン

| 部位 | 調達先 |
|---|---|
| フレーム | CFRPのパイプ・板材 |
| ベアリング | セラミックベアリング |
| シャフト | チタンボルト、ステンレス |
| コーティング | DLC加工の業者へ外注 |

## 4. コスト感

### M-1・M-2(地上の概念実証機): 総額12〜25万円

| 項目 | 概算 |
|---|---|
| CFRPフレーム | 3〜5万円 |
| セラミックベアリングのモーター×4 | 5〜10万円 |
| エアロゲル + 断熱材 | 1〜3万円 |
| ヒーター + 温度制御 | 1〜2万円 |
| TMR冗長のESP32構成 | 1〜2万円 |
| DLCコーティングの外注 | 1〜3万円 |

### M-3(宇宙用の素材・本格仕様): 総額100〜300万円

| 項目 | 概算 |
|---|---|
| 宇宙用の断熱材 | 10〜30万円 |
| 放射線耐性部品 | 50〜200万円 |
| チタン構造材の加工 | 20〜50万円 |
| 低温対応バッテリー | 10〜30万円 |
| 試験・認定の費用 | 別途 |

### 核心: 支配的なコストは「素材」ではない

| | コスト |
|---|---|
| 動くものを作る | 数十万円 |
| 火星で動くと証明する | 数百万〜数千万円 |

M-3からM-4で資金調達が必要になるのは、「試験と認定」が支配的なコストになるから。

## 5. 設計思想まとめ

| 環境 | 設計思想 |
|---|---|
| 極低温 | バッテリーを中心に守る「マトリョーシカ設計」 |
| 放射線 | 壊れる前提で、ソフトウェアが自己修復する |
| 砂塵 | 場所ごとに素材を選び、トレードオフを制御する |

**共通思想: 「完璧に防ぐ」のではない。「壊れても動き続ける」設計。**
